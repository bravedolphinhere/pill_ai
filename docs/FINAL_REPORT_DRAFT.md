# 내부 알약 데이터 YOLO11n 베이스라인 보고서 초안

작성일: 2026-11-05. 제출 마감: 당일 17:00 KST.
**현재 상태:20epoch 학습·평가 완료. 제출에는 [최종 보고서](FINAL_REPORT.md)를 사용한다.**

## 목적

내부 알약 사진에서 위치와 제품 클래스를 검출하는 YOLO11n 기준 모델을 구축한다.
외부 데이터의 라벨 체계·품질 위험이 달라 이번 기준 실험에는 사용하지 않는다.
확인된 문제와 불확실한 데이터는 원본을 수정하지 않고 사진 단위로 격리한다.

## 데이터와 분석 근거

기존 내부 EDA 기준 학습 사진 232장, 알약별 JSON 763개, 제품 클래스 56개다.
별도 test 이미지 842장에는 평가용 정답이 없어 정량 평가에 사용하지 않는다.
클래스별 라벨 수는 3~153개로 불균형하고 17클래스는 촬영 조합이 하나뿐이다.
기존 EDA에서 화면 밖 bbox 1개, 면적 불일치 6개, 클래스 충돌 3쌍,
파일명 기대 코드 연결 누락 후보 8개를 확인했다. 이 수들을 더해 고유 오류 이미지 수로 해석하지 않는다.
실제 알약 수·제품 정체는 JSON만으로 확정하지 않는다.

분석 노트북: `notebooks/01_internal_data_eda.ipynb`, `notebooks/02_external_data_eda.ipynb`.
GitHub용 사본은 원본 이미지 첨부·코드 출력을 제외하고 로컬 EDA 결과를 연결한다.

## 방법과 재현 조건

- 원본 `[x,y,w,h]`를 검증한 뒤 YOLO의 정규화 중심·너비·높이로 변환한다.
- 원본 제품 코드·클래스 ID와 연속 YOLO ID의 대응을 기록한다.
- 촬영 조합·동일/유사 이미지 그룹을 그대로 유지한80.2:19.8 분할을 사용한다.
- split 누수와 클래스별 validation support를 기록한다.
- 설정: YOLO11n pretrained, epochs20, imgsz640, batch8, seed42.
- RTX 5070 12GB. Python3.14.2/PyTorch2.14.0+cu130/Ultralytics8.4.193에서
  작은 CUDA 행렬과 torchvision NMS 연산은 통과했다.
- 프로젝트 기본 Python3.12/cu126은 GPU 인식 뒤 실제 연산에 실패해 그대로 학습에 사용하지 않는다.

실제 데이터 QA·변환은 사용자 승인 후 실행했다.
PASS197장/라벨660개를 남기고 REVIEW35장/라벨103개를 사진 단위 보류했다.
56클래스는 모두 유지했으며 최신 분할은 train158장/528개 라벨/56클래스,
validation39장/132개 라벨/29클래스다.
기존65:35 분할을 보존하고, 동일한 그룹·QA 판정·라벨에서 사진 비율을 우선해 재분할했다.
197장의20%가39.4장이므로39장을 검증으로 두는80.2:19.8이 가장 가깝다.
그 조건 안에서 검증 클래스 범위를 최대화했으며29클래스를 유지했다.
원본232사진·763JSON 지문, 복사197사진과 YOLO 라벨660개의 원본 좌표 역변환을 검증했다.
정의한 촬영·해시·유사 그룹 기준 split 누수는0건이다.
사용자 승인 후20epoch 학습과 best.pt의 별도 validation 평가를 완료했다.

## 한계와 후속 작업

자동 검사 통과는 라벨 의미의 정확성 보증이 아니다.
알약 정체 확인에는 사진의 가시적 특징과 독립 제품 정보 대조가 필요하다.
희소 클래스·반복 촬영 때문에 validation에서 빠진 클래스의 성능은 이 실험으로 평가할 수 없다.
이미 EDA/QA에 노출된 validation 성능을 독립 test 성능으로 주장하지 않는다.
PASS에서 클래스별로 추출한56어노테이션/49사진의 감사는 사람 검수 대기 상태다.
PASS 표본 사람 검수와 독립 test 평가가 후속 과제다.
GitHub에는 코드·문서·이미지 미포함 EDA만 제출하고 원본 데이터·가중치·개인 환경 경로·인증키는 제외한다.
